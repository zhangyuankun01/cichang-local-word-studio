# 词场：学习流程与微信小程序检查记录

更新日期：2026-09-29。

## 迁移难度判断

当前桌面应用是 Electron + React + Vite；小程序采用原生 WXML/WXSS 和微信 API。JavaScript 数据模型、复习计算、文件文本解析适合复用；React DOM 界面、Electron IPC、本机 Piper 程序和浏览器 Audio 不能直接放进原生小程序。迁移难度中等，主要工作在手机交互、存储、音频和发布接入，不能以网页引擎相似为依据认为可以直接换壳。

微信官方也提供 Skyline 渲染引擎，说明小程序并不统一等同于浏览器页面：[微信官方 Skyline 示例仓库](https://github.com/wechat-miniprogram/awesome-skyline)。本项目当前仍使用常规小程序渲染配置。

## 参考产品与设计取舍

- [Anki 的答题说明](https://docs.ankiweb.net/studying.html)：回想后核对答案，区分遗忘和回想困难。Anki 的 Hard 是“答对但困难”，不是遗忘。
- [Anki 的学习与重学步骤](https://docs.ankiweb.net/deck-options.html)：初学与成熟词的安排不同，答错回到重学；过多同日重复不能等同于长期掌握。
- [Quizlet Write 模式](https://help.quizlet.com/hc/en-us/articles/360030990531-Studying-with-Write-mode)：错误项会继续练习，提供结果纠正操作。

词场沿用按答题数量推进的产品约定。这次参考的是主动回想、分档反馈、重学、误判纠正和控制学习负担等原则。下面的题数、阶段和上限是本产品的可解释规则，不是上述产品公开算法的复制，也没有经过学习效果实验验证。

## 当前实际规则

答题前隐藏中文释义、英文例句与例句翻译，避免上下文泄露答案。听音模式还隐藏拼写和音标。选择认识/模糊/不认识后才显示答案，用户核对后进入下一题；如果原来选认识或模糊，却发现想错了，可改为不认识，原评分的统计和排期会被撤销，不多算一次答题。主动点“想不起来，显示答案”按不认识处理。

| 选择 | 本轮处理 | 后续阶段 |
| --- | --- | --- |
| 不认识 | 尽量隔 2 道其他题重练；连续认识次数归零 | 成熟词最多退 2 阶段，保留其他记录 |
| 模糊 | 尽量隔 4 道其他题重练；不计为认识，连续认识次数归零 | 成熟词最多退 1 阶段 |
| 认识 | 初学/重学词第一次认识后尽量隔 6 道再核对；连续认识 2 次进入巩固 | 已在巩固的词再认识可前进一阶段；间隔为 12、24、48、96、192、384 次全局答题 |

- 本轮其他题不足时，实际间隔会缩短，反馈显示实际题数；只剩一个词时明确提示下一题重练。
- 同一词在一轮累计作答 6 次仍未完成时，明确提示暂停，保留在待复习中；用户可主动开始下一轮继续练。
- 每日新词/复习目标按不同词条计数。同日换一轮或同轮重试不重复消耗额度。未完成的重学词仍可继续，不因每日额度而丢掉。
- 正常队列完成后不再自动提前拿出成熟词。需要继续时点“额外巩固”；不会伪装成仍有到期任务。
- “已掌握”仅表示进入巩固阶段，不代表永久不会遗忘；统计中的“认识反馈率”是自评数据，不是客观测验准确率。

## 已发现并修复的问题

| 原问题 | 影响 | 当前处理 |
| --- | --- | --- |
| 答题前直接显示中文和例句 | 判断被提示污染 | 评分前不渲染答案，评分后核对 |
| 只有认识/不会 | 无法区分不确定程度 | 两端统一增加模糊及独立统计 |
| 桌面仍保留独立评分函数 | 共享规则变更无法同步 | 桌面和小程序评分均调用 shared/domain.js |
| 跨轮把新词重练再计为复习 | 每日额度被重复扣除 | 每日保存已见词 ID，并兼容旧记录 |
| 六阶复习读档被截成五阶 | 最高阶段进度丢失 | 恢复时保留第六阶段 |
| 重复插入待练词、无限反复 | 队列膨胀、难以结束 | 每词最多一条未来重试，六次后明确暂缓 |
| 误判后不能修正 | 统计和下次复习失真 | 当前反馈页可改为不认识，回滚原评分 |
| CSV/TXT 被无条件当作 JSON 解析 | 普通词库导入失败 | 使用从桌面解析器生成的同源小程序模块 |
| 没有导入预览，错误行与重复项不透明 | 导入结果不清楚 | 确认前显示有效/重复/错误行，支持跳过或更新释义 |
| 新增词缺少字段、无法编辑 | 搜索可报错，中文无法补全 | 完整字段默认值，添加/编辑/删除及 CSV 导出 |
| 音频准备和点击播放可能重复请求 | 浪费请求与等待 | 同词复用正在执行的请求 |
| 后台生成完成主动播放、创建多个播放器 | 打断当前题目、音频重叠 | 后台只缓存，使用一个播放器，切页/切题停止旧播放 |
| 音频回调重置答案状态 | 正在核对时答案消失 | 显示状态始终由当前答题反馈决定 |
| 原始整本词库（含音频）传到 setData | 大词库更新负担大 | 仅传展示字段，词库每页 50 个，音频不传渲染层 |
| 损坏存储静默变为演示词库并覆盖 | 原数据可能丢失 | 保留原存储，阻止普通写入，允许明确恢复备份 |
| 异步写入没有顺序保证 | 较旧状态可能覆盖较新状态 | 同步提交元数据，成功后才更新内存状态 |
| 文档和代码对备份音频的描述不一致 | 不知道能否迁移 | 完整 JSON 导出包含可读取音频；恢复后落到本机缓存 |
| Worker 源码位于小程序项目根下 | 服务端文件混入客户端包 | 项目打包排除 cloudflare-worker 目录 |

## 验证范围与剩余工作

使用 Node 场景测试覆盖实际共享模块、React 服务器渲染的隐藏答案、模拟微信 API 下的页面/导入/音频/存储流程；另做 TypeScript 检查和桌面构建。模拟微信 API 的测试不等于微信真机验证。

仍有这些限制：

1. 按题数排期不会自动考虑离开应用的天数，因此不是长期遗忘预测算法。很小的词库完成后，可能需要手动点额外巩固。若要按遗忘时间自动提醒，需要另行加入可选的日期调度模式，并评估与题数模式如何兼容。
2. 现有 18 个演示词不等于完整词典。仅含英文的导入文件不会自动获得中文释义；可在词条编辑中补充。在线发音也不会生成词义。
3. 当前无微信云端同步；数据在本机，需自行导出备份。音频仍受微信沙箱容量限制；保存失败会报错，尚未加入完整的音频空间管理界面。
4. TTS 服务地址为空，Worker 尚未部署；可先用桌面含录音的备份测试离线播放。正式在线发音需要接通服务、身份校验与限流。
5. 尚未在微信开发者工具和 iOS/Android 真机完成编译、布局、后台恢复、录音格式与文件分享验证；不能宣称已达到上架状态。
6. AppID、生产 HTTPS 域名及微信平台配置仍待提供/完成；本次未部署 Worker 或发布小程序，也未更新已安装的桌面安装包。

可复现命令：`npm run test:study`、`node node_modules/typescript/bin/tsc --noEmit`、`npm run build`。
